---
name: rnt-convert
description: Stage 2 - convert the clean NanoAOD files of one masspoint to RNTuple on HTCondor, record results in conversion.csv.
---
`bash scripts/rnt_run_mp.sh <mp> convert [--branches CONF]`: manifest -> gate P -> `python/rnt_make_jobs.py --manifest` (ONE group per condor job; refuses a changed manifest/source or conflicts) -> condor (`scripts/rnt_convert.sh`: `bin/rnt_convert --inputs <sources> --compression 512` in worker scratch, copy to `<out>.part.<pid>`, rename; an existing stale output is first renamed into `/pnfs/.../RNTuple_superseded/<date>/<mp>/`) -> missing chunks resubmitted max 2x (jobs running > 1 h are removed by `periodic_remove`) -> `python/rnt_aggregate.py` -> `results/<mp>/rntuple/{conversion.csv,groups.csv}` -> gate B. Run dir `results/<mp>/rntuple/runs/<run_id>/`.
The merged file keeps source order: Events = all events; Runs and LuminosityBlocks = one entry per source. conversion.csv (one row per OUTPUT): status, n_sources, group_digest, events expected/entries, input/output bytes, trees converted/skipped, branches kept/dropped, toolchain digest, ROOT version, seconds, superseded, error. groups.csv = provenance (output, input, events, size, mtime). Gate B: every planned output ok, built from the current sources (group digest), current toolchain digest, size as recorded, no `.part.*`/`.failed`, no output beyond the plan. Conversion never deletes anything.
